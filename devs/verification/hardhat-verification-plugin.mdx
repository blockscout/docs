[Hardhat](https://hardhat.org/) is a full-featured development environment for contract compilation, deployment and verification. The [hardhat-verify plugin](https://hardhat.org/hardhat-runner/plugins/nomicfoundation-hardhat-verify) supports contract verification on Blockscout.

<Warning>
  This guide targets **Hardhat 2** and `@nomicfoundation/hardhat-verify@hh2`. Hardhat 3's default `hardhat-verify` (v3) has native Blockscout support, but its Blockscout provider currently has no `apiKey` field, so the Pro API can't be used for verification there. Until that's resolved  use this Hardhat 2 / Pro API setup as the working path.
</Warning>

## Get Started

### **1) Install Hardhat**

If you are starting from scratch, create an npm project by going to an empty folder, running `npm init`, and following the instructions. Recommend npm 7 or higher.

Once your project is ready:

**npm instructions**

```sh
npm install --save-dev hardhat
```

**yarn instructions**

```sh
yarn add --dev hardhat
```

### **2) Create a project**

Run `npx hardhat` in your project folder and follow the instructions to create ([more info here](https://hardhat.org/getting-started/#quick-start)).

### 3) Install plugin

Install the [hardhat-verify plugin](https://hardhat.org/hardhat-runner/plugins/nomicfoundation-hardhat-verify)

**npm**

```sh
npm install --save-dev @nomicfoundation/hardhat-verify@hh2
```

**yarn**

```sh
yarn add --dev @nomicfoundation/hardhat-verify@hh2
```

### 4) Add plugin reference to config file

Note the `@hh2` tag above — plain `npm install @nomicfoundation/hardhat-verify` now installs v3 (Hardhat 3), which is the version with the Pro API gap described above.

Add the following statement to your `hardhat.config.js`.

```javascript
require("@nomicfoundation/hardhat-verify");
```

If using TypeScript, add this to your `hardhat.config.ts.` [More info on using typescript with hardhat available here](https://hardhat.org/guides/typescript.html#typescript-support).

```ts
import "@nomicfoundation/hardhat-verify";
```

## Config File and Unsupported Networks

Your basic [Hardhat config file](https://hardhat.org/config/) (`hardhat.config.js` or `hardhat.config.ts`) will be setup to support the network you are working on. In this example we use Robinhood Chain and a `.ts` file.

In order to use Blockscout explorer for the verification, you have to specify the explorer details under a `customChains` object. It includes:

- `chainId` - Network chain ID
- `apiURL` - Block explorer API URL
- `browserURL` - Block explorer URL

<Info>
  Find an extensive list of ChainIDs at [https://chainlist.org/](https://chainlist.org/).
</Info>

Point the plugin at Blockscout's [Pro API](/devs/pro-api-responses-and-routes), which gives you higher rate limits and a single, unified route across every chain Blockscout supports — `https://api.blockscout.com/{chain_id}/api` — instead of a separate per-instance subdomain for each one.

<Check>
  Get a free Pro API key at [https://dev.blockscout.com/](https://dev.blockscout.com/)
</Check>

Because the same key works for every chain, `etherscan.apiKey` can be a **plain string** rather than an object keyed by network name — this is confirmed by the [hardhat-verify plugin's own docs](https://hardhat.org/hardhat-runner/plugins/nomicfoundation-hardhat-verify#usage).

Store both your deployer key and your Pro API key using [Hardhat's configuration variables](https://hardhat.org/hardhat-runner/docs/guides/configuration-variables):

```sh
npx hardhat vars set PRIVATE_KEY
npx hardhat vars set BLOCKSCOUT_API_KEY
```

Here we add Blockscout's Pro API endpoints for Robinhood Chain to the config file:

```ts
import { HardhatUserConfig, vars } from "hardhat/config";
import "@nomicfoundation/hardhat-toolbox";
import "@nomicfoundation/hardhat-verify";

const PRIVATE_KEY = vars.get("PRIVATE_KEY");
const BLOCKSCOUT_API_KEY = vars.get("BLOCKSCOUT_API_KEY");

const config: HardhatUserConfig = {
  solidity: "0.8.24",
  networks: {
    'robinhood-chain': {
      url: 'https://rpc.mainnet.chain.robinhood.com',
      accounts: [PRIVATE_KEY],
      chainId: 4663,
    },
  },
  etherscan: {
    apiKey: BLOCKSCOUT_API_KEY,
    customChains: [
      {
        network: "robinhood-chain",
        chainId: 4663,
        urls: {
          apiURL: "https://api.blockscout.com/4663/api",
          browserURL: "https://robinhoodchain.blockscout.com/",
        }
      }
    ]
  },
  sourcify: {
    enabled: false
  }
};

export default config;
```

### Verifying on multiple chains?

If you deploy to more than one network, you don't need a separate config block per chain. Since the Pro API key is the same everywhere, define your chains once in an array and generate `networks` and `customChains` from it:

```ts
import { HardhatUserConfig, vars } from "hardhat/config";
import "@nomicfoundation/hardhat-toolbox";
import "@nomicfoundation/hardhat-verify";

const PRIVATE_KEY = vars.get("PRIVATE_KEY");
const BLOCKSCOUT_API_KEY = vars.get("BLOCKSCOUT_API_KEY");

// Single source of truth for every chain you deploy to.
// Add a new chain by adding one line here — no need to touch
// `networks` or `customChains` separately.
const CHAINS = [
  { network: "robinhood-chain", chainId: 4663, rpc: "https://rpc.mainnet.chain.robinhood.com", explorer: "robinhoodchain" },
  { network: "base", chainId: 8453, rpc: "https://mainnet.base.org", explorer: "base" },
  { network: "optimism", chainId: 10, rpc: "https://mainnet.optimism.io", explorer: "optimism" },
  { network: "arbitrum-one", chainId: 42161, rpc: "https://arb1.arbitrum.io/rpc", explorer: "arbitrum" },
];

const config: HardhatUserConfig = {
  solidity: "0.8.24",
  networks: Object.fromEntries(
    CHAINS.map(({ network, chainId, rpc }) => [
      network,
      { url: rpc, accounts: [PRIVATE_KEY], chainId },
    ])
  ),
  etherscan: {
    // Confirmed by hardhat-verify docs: a single string applies to every network
    apiKey: BLOCKSCOUT_API_KEY,
    customChains: CHAINS.map(({ network, chainId, explorer }) => ({
      network,
      chainId,
      urls: {
        apiURL: `https://api.blockscout.com/${chainId}/api`,
        browserURL: `https://${explorer}.blockscout.com/`,
      },
    })),
  },
  sourcify: {
    enabled: false,
  },
};

export default config;
```

<Info>
  Run `npx hardhat verify --list-networks` at any time to confirm which network identifiers are registered in your config.
</Info>

## Deploy and Verify

For deployment we will use [Hardhat Ignition](https://hardhat.org/ignition/docs/getting-started#overview) - built-in Hardhat deployment system.

### Deploy

```txt
> npx hardhat ignition deploy ./ignition/modules/Lock.ts --network robinhood-chain
✔ Confirm deploy to network robinhood-chain (4663)? … yes
Compiled 1 Solidity file successfully (evm target: paris).
Hardhat Ignition 🚀

Deploying [ LockModule ]

Batch #1
  Executed LockModule#Lock

[ LockModule ] successfully deployed 🚀

Deployed Addresses

LockModule#Lock - 0xFE826b33e425f99ce962ACB91752DB41F302EFEA
```

### Verify

The plugin requires you to include constructor arguments with the verify task and ensures that they correspond to expected ABI signature. However, Blockscout ignores those arguments, so you may specify any values that correspond to the ABI.

```sh
npx hardhat verify --network <network> DEPLOYED_CONTRACT_ADDRESS "Constructor argument 1"
```

Robinhood Chain example.

```sh
> npx hardhat verify --network robinhood-chain 0xFE826b33e425f99ce962ACB91752DB41F302EFEA 1234
Successfully submitted source code for contract
contracts/Lock.sol:Lock at 0xFE826b33e425f99ce962ACB91752DB41F302EFEA
for verification on the block explorer. Waiting for verification result...

Successfully verified contract Lock on the block explorer.
https://robinhoodchain.blockscout.com/address/0xFE826b33e425f99ce962ACB91752DB41F302EFEA#code
```

If you're using the multi-chain config, the same command works unchanged for any chain in your `CHAINS` array — just swap `--network robinhood-chain` for `--network base`, `--network arbitrum-one`, etc.

### Automatically verified contracts

Sometimes the contract may be automatically verified via [Ethereum Bytecode Database](https://docs.blockscout.com/about/features/ethereum-bytecode-database-microservice#solution-ethereum-bytecode-database-blockscout-ebd) service. In that case you may see the following response:

```txt
The contract 0xFE826b33e425f99ce962ACB91752DB41F302EFEA has already been verified on Etherscan.
https://robinhoodchain.blockscout.com/address/0xFE826b33e425f99ce962ACB91752DB41F302EFEA#code
```

In that case, you may try to enforce using `--force` flag\*.

It prevents Hardhat from checking if the contract is already verified, and force it to send verification request anyway. Notice, that it is helpful only if the contract was automatically verified **partially**. That way, a new verification sources would be saved. If the contract was **fully** verified already, that just returns an error.

```sh
npx hardhat verify --network <network> DEPLOYED_CONTRACT_ADDRESS "Constructor argument 1" --force
```

- The flag is available starting from `@nomicfoundation/hardhat-verify@2.0.7`

## FAQ

<Accordion title="I am using an OpenZeppelin upgrades plugin implementation and receive an error on proxy contract verification. What should I do?">
  Although you receive an error, the contracts should be verified during the previous steps and you can ignore. Check in the explorer to make sure the contracts have been verified.
</Accordion>

<Accordion title="Do I need a different API key for each chain?">
  No. The Pro API uses a single key across every chain Blockscout supports, so `etherscan.apiKey` can be set once as a plain string instead of a per-network object. See the [Pro API docs](/devs/pro-api-responses-and-routes) for details.
</Accordion>
